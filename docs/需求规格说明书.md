## 1. 引言

### 1.1 编写目的

本文档旨在明确"美食信息可视化平台"的功能需求、性能需求及系统边界，为项目开发、测试、验收提供依据。

### 1.2 项目背景

- **项目名称**：foodie-map 美食信息可视化平台
- **项目目标**：构建面向南昌旅游景点的特色美食信息可视化系统，通过数据采集、分析、可视化展示，帮助游客快速发现高性价比美食
- **目标用户**：来南昌旅游的游客、本地美食爱好者

### 1.3 术语定义

| 术语 | 定义 |
|------|------|
| POI | Point of Interest，兴趣点，本文指美食店铺 |
| 性价比指数 | 评分与人均消费的比值，用于衡量店铺性价比 |
| 热力图 | 基于地理坐标的数据密度可视化图表 |
| 爬虫 | 自动化数据采集程序 |

### 1.4 参考资料

- 高德地图开放平台文档：https://lbs.amap.com/
- 大众点评开放平台规范
- RESTful API设计规范

## 2. 项目概述

### 2.1 项目目标

1. **数据采集**：自动化采集南昌地区美食店铺数据
2. **数据分析**：构建多维度排行榜（综合评分、性价比、热门度）
3. **可视化展示**：地图展示、排行榜、数据筛选
4. **辅助决策**：为游客提供美食选择参考

### 2.2 用户群体

| 用户类型 | 特征 | 核心需求 |
|----------|------|----------|
| 游客 | 来南昌旅游，不熟悉本地美食 | 快速找到景点周边高性价比美食 |
| 美食爱好者 | 本地居民，喜欢探索新店 | 发现热门店铺、分类排行榜 |
| 平台管理员 | 系统维护人员 | 数据管理、系统监控 |

### 2.3 运行环境

**服务端：**
- 操作系统：Linux / Windows Server
- JDK：OpenJDK 21
- 数据库：MySQL 9.0
- 缓存：Redis 5.x

**客户端：**
- 浏览器：Chrome 90+ / Firefox 88+ / Safari 14+
- 分辨率：1920x1080 及以上（适配移动端）

#### 3.2.2 数据分析模块（核心）

> 本模块是项目的核心亮点，直接对应作业要求中的"提取城市当地特色可能出现的问题"和"基于个人消费情况分析性价比"

**功能编号：F-004**
**功能名称：当地特色分析**

| 项目 | 描述 |
|------|------|
| 功能描述 | 分析各城市当地美食特色，识别当地美食发展中存在的问题 |
| 输入 | 多平台爬取的店铺数据、评论数据 |
| 输出 | 当地特色分析报告（可视化图表） |
| 分析维度 | 1. **当地特色菜品识别**：统计各城市高频出现的菜品/标签，提取当地特色美食<br>2. **特色店铺分布**：分析当地特色美食店铺的地理分布规律<br>3. **价格与评分关系**：分析当地特色美食是否存在"名气大但性价比低"的问题<br>4. **游客评价分析**：提取评论中的高频关键词，识别游客对当地美食的正面/负面反馈<br>5. **问题识别**：如"网红店评分虚高"、"本地人不去的店"、"价格虚高"等 |
| 可视化输出 | 词云图（当地特色菜品）、散点图（价格vs评分）、柱状图（各分类评分对比）、情感分析图 |

**功能编号：F-005**
**功能名称：个人消费性价比分析**

| 项目 | 描述 |
|------|------|
| 功能描述 | 基于个人消费场景（如学生、上班族、家庭），分析不同消费水平下的性价比最优选择 |
| 输入 | 店铺数据（评分、价格、分类等） |
| 输出 | 分消费场景的性价比推荐 |
| 分析逻辑 | 1. **定义消费场景**：经济型（<30元/人）、大众型（30-80元/人）、品质型（80-150元/人）、高端型（>150元/人）<br>2. **计算性价比指数**：性价比 = 评分 / 人均消费 × 100，按消费场景分组<br>3. **多维度性价比**：口味性价比、环境性价比、服务性价比（如数据支持）<br>4. **推荐策略**：每个消费场景推荐TOP10高性价比店铺 |
| 可视化输出 | 雷达图（多维度性价比对比）、气泡图（价格-评分-推荐度）、分组柱状图（各消费场景TOP店铺） |

**功能编号：F-006**
**功能名称：多城市对比分析**

| 项目 | 描述 |
|------|------|
| 功能描述 | 对2-3个省会城市的美食数据进行对比分析，发现各城市美食特点差异 |
| 输入 | 多个城市的爬取数据 |
| 输出 | 城市对比分析报告 |
| 分析维度 | 1. **整体消费水平对比**：各城市人均消费分布<br>2. **评分差异**：各城市平均评分对比<br>3. **特色分类对比**：各城市热门美食分类差异<br>4. **性价比差异**：同等评分下各城市价格差异<br>5. **推荐指数**：综合性价比最优的城市推荐 |
| 目标城市 | 南昌（主）、武汉、长沙（可扩展） |
| 可视化输出 | 分组柱状图、雷达图（城市多维度对比）、热力图（各城市美食分布） |

#### 3.2.3 排行榜模块

**功能编号：F-007**
**功能名称：综合评分排行榜**

| 项目 | 描述 |
|------|------|
| 功能描述 | 按店铺综合评分排序，展示TOP N店铺 |
| 输入 | 榜单数量N（默认10，最大100） |
| 输出 | 排序后的店铺列表 |
| 排序规则 | 按rating字段降序，同分按评论数降序 |
| 缓存策略 | Redis ZSet存储，每5分钟刷新 |

**功能编号：F-008**
**功能名称：性价比排行榜（个人消费视角）**

| 项目 | 描述 |
|------|------|
| 功能描述 | 按消费场景分组，推荐各场景下性价比最高的店铺 |
| 输入 | 榜单数量N、消费场景（economic/popular/quality/premium） |
| 输出 | 指定消费场景下的TOP店铺列表 |
| 计算公式 | 性价比指数 = (评分 / 人均消费) × 100 |
| 消费场景 | economic(<30元)、popular(30-80元)、quality(80-150元)、premium(>150元) |
| 排序规则 | 按性价比指数降序 |

**功能编号：F-009**
**功能名称：热门排行榜**

| 项目 | 描述 |
|------|------|
| 功能描述 | 按店铺浏览量/收藏量排序 |
| 输入 | 榜单数量N、时间范围（今日/本周/本月） |
| 输出 | 排序后的店铺列表 |
| 排序规则 | 按view_count字段降序 |

**功能编号：F-010**
**功能名称：分类排行榜**

| 项目 | 描述 |
|------|------|
| 功能描述 | 按美食分类展示各分类TOP店铺 |
| 输入 | 分类名称、榜单数量N |
| 输出 | 该分类下的TOP店铺列表 |
| 分类定义 | **动态分类**：根据实际爬取数据自动生成分类列表，不预设固定分类 |
| 分类生成逻辑 | 1. 爬取数据时记录各平台的分类标签<br>2. 数据入库后统计分类频次<br>3. 高频分类自动纳入排行榜<br>4. 支持手动合并/重命名分类 |

## 5. 数据需求

### 5.1 数据采集策略

> **重要说明**：本系统所有数据均来自爬虫采集，数据实体字段根据实际爬取结果动态调整。
> 
> - 不同平台数据字段可能不同，系统需做字段映射和兼容
> - 分类、标签等枚举值根据爬取数据动态生成
> - 图片、视频等多媒体数据需下载存储

**数据源优先级：**

| 优先级 | 平台 | 数据特点 | 采集难度 |
|--------|------|----------|----------|
| 1 | 大众点评 | 店铺基础信息完整、评分权威 | 中等 |
| 2 | 美团 | 价格信息、优惠活动 | 中等 |
| 3 | 小红书 | UGC内容、实拍图、网红店 | 较高 |
| 4 | 抖音 | 探店视频、热度数据 | 较高 |

### 5.2 数据实体

**店铺 (Shop)**

> 字段定义基于爬取数据，以下为核心字段，实际字段根据爬取结果扩展

| 字段名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| id | BIGINT | 是 | 主键，自增 |
| shop_id | VARCHAR(50) | 是 | 店铺唯一标识 |
| name | VARCHAR(100) | 是 | 店铺名称 |
| category | VARCHAR(50) | 否 | 美食分类（动态生成） |
| address | VARCHAR(255) | 否 | 详细地址 |
| longitude | DECIMAL(10,7) | 否 | 经度 |
| latitude | DECIMAL(10,7) | 否 | 纬度 |
| rating | DECIMAL(2,1) | 否 | 综合评分(0-5) |
| price_avg | INT | 否 | 人均消费(元) |
| phone | VARCHAR(20) | 否 | 联系电话 |
| business_hours | VARCHAR(100) | 否 | 营业时间 |
| tags | VARCHAR(255) | 否 | 标签，逗号分隔 |
| source | VARCHAR(20) | 否 | 数据来源 |
| view_count | INT | 否 | 浏览次数，默认0 |
| **shop_image** | VARCHAR(500) | 否 | **店铺封面图片URL** |

| **food_images** | TEXT | 否 | **美食图片列表（JSON数组）** |

| create_time | DATETIME | 是 | 创建时间 |
| update_time | DATETIME | 是 | 更新时间 |

**图片存储说明：**

> 图片统一存储于**阿里云 OSS**（对象存储服务），数据库中仅存储 OSS 访问 URL。爬虫采集到图片后自动上传至 OSS，前端通过 CDN 加速域名加载图片。

| 图片类型 | 来源 | 存储方式 | 用途 |
|----------|------|----------|------|
| 店铺封面 | 各平台店铺主图 | OSS: shop/cover/{shop_id}/main.jpg | 列表展示、详情页 |
| 店铺相册 | 各平台店铺图片 | OSS: shop/album/{shop_id}/，URL 以 JSON 数组存入 DB | 详情页轮播 |
| 美食图片 | 小红书笔记图片、用户实拍 | OSS: shop/food/{shop_id}/，URL 以 JSON 数组存入 DB | 详情页、美食展示 |
| 视频封面 | 抖音视频封面 | OSS: shop/cover/{shop_id}/video_thumb.jpg | 视频入口展示 |

## 7. 项目约束

### 7.1 技术约束

- 后端必须使用SpringBoot框架
- 必须体现面向对象特性（封装、继承、多态）
- 数据存储必须使用文件形式（TXT/XML/JSON），禁止二进制存储
- 必须使用Redis作为缓存
- 图片资源统一存储于阿里云 OSS，数据库仅存访问 URL

### 7.2 时间约束

- 项目周期：5周
- 里程碑：
  - Week 1：需求分析 + 架构设计
  - Week 2：数据采集
  - Week 3：后端开发
  - Week 4：前端开发
  - Week 5：测试部署

### 7.3 法律约束

- 数据采集需遵守目标网站的Robots协议
- 不得采集用户隐私数据
- 数据仅用于学习研究，不得商用
